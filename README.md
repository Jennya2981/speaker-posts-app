# Сбор постов от спикеров

Веб-приложение для сбора, хранения и подготовки постов от спикеров перед публикацией в соцсетях (Telegram и др.).

## Возможности

- ✍️ **Создание постов** — заголовок, текст, хештеги; выбор автора из выпадающего списка
- 📝 **Черновики** — сохранение черновика с плашкой «Черновик» и последующей публикацией
- ➕ **Добавление спикеров** на лету, прямо при создании поста
- 📋 **Все посты** — список с фильтрацией по ФИО спикера, сортировкой по имени и счётчиками «Опубликовано» / «Черновики»
- 🔍 **Просмотр поста** — клик по карточке открывает полный текст
- 📤 **Копирование** в нескольких вариантах:
  - «Копировать для Telegram» — текст + хештеги без заголовка
  - «Копировать весь пост» — заголовок + текст + хештеги
  - копирование по отдельным полям
- ✏️ **Редактирование и удаление** постов прямо в приложении
- 🎨 Фирменные цвета: кнопки #4338CA, плашка черновика #818CF8

## Быстрый запуск (статическая версия)

Приложение можно использовать **без установки чего-либо** — как обычную веб-страницу:

```bash
# 1. Перейти в папку со статическими файлами
cd static

# 2. Открыть index.html в любом браузере
# (двойным кликом по файлу или через командную строку)
start index.html    # Windows
open index.html     # macOS
```

Данные сохраняются в `localStorage` вашего браузера — посты и спикеры остаются между перезагрузками страницы.

## Быстрый старт

Требуется **Node.js 18+** (https://nodejs.org).

```bash
# 1. Клонировать репозиторий
git clone <URL-вашего-репозитория>
cd speaker-posts-app

# 2. Создать файл .env из примера
cp .env.example .env          # macOS/Linux
copy .env.example .env        # Windows

# 3. Установить зависимости
npm install

# 4. Создать базу данных (если её нет)
npm run db:push

# 5. Заполнить спикерами (по желанию)
npm run db:seed

# 6. Запустить
npm run dev
```

Откройте http://localhost:3000 в браузере.

> 💡 В репозитории уже лежит файл базы данных `db/custom.db` с текущими данными.
> Если нужна чистая база — удалите файл `db/custom.db` и выполните `npm run db:push`, затем `npm run db:seed`.

## Модель данных

**Speaker (спикер):** `id`, `name` (уникальное ФИО), `createdAt`

**Post (пост):** `id`, `title`, `content`, `hashtags`, `status` (`PUBLISHED` / `DRAFT`), `speakerId` → Speaker, `createdAt`, `updatedAt`

## API

| Метод | Маршрут | Описание |
|-------|---------|----------|
| GET | `/api/posts` | все посты с именами спикеров |
| POST | `/api/posts` | создать пост (`status: PUBLISHED` требует `speakerId`) |
| PATCH | `/api/posts/:id` | частичное обновление поста |
| DELETE | `/api/posts/:id` | удалить пост |
| GET | `/api/speakers` | список спикеров |
| POST | `/api/speakers` | создать спикера (или вернуть существующего) |

## Резервная копия данных

Все посты и спикеры хранятся в одном файле `db/custom.db` — для бэкапа достаточно скопировать этот файл. Пример выгрузки в JSON лежит в папке `Post_for_arup` рядом с проектом.

## Работа с Prisma

```bash
npm run db:studio    # визуальный редактор БД (Prisma Studio)
npm run db:generate  # перегенерировать Prisma Client после изменения схемы
npm run db:push      # применить изменения схемы к БД
```
